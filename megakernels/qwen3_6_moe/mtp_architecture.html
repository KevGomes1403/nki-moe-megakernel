Qwen3.6-35B-A3B — fused speculation graph

One EAGLE round — draft, verify, replay, accept, commit — in a single static graph. speculation_length = 2 (k = 1 drafted token). All source refs are modeling_qwen36_a3b.py.

Notation

The MTP head is one decoder layer (full GQA + 256-expert MoE) with its own KV cache, so it attends over its own history and every round must leave a well-formed entry behind. embed_tokens and lm_head are tied to the main model.

Prefill · runs once

③ Replay MTP head · unconditional :4582

MTP re-run over the whole block at slots [t, t+1] with prev_hidden = [ht, ht+1]:
  • slot t ← (ht, embed(xt+1)) — identical to ①; orig_hidden is stashed at :4533 so it reproduces exactly.
  • slot t+1 ← (ht+1, embed(xt+2draft)) — the entry that could not exist before now.

It covers the whole block because the draft loop feeds its own output hidden forward (hidden_state = model_output[-1] :4551): at spec_len > 2, slots t+1 … t+k-1 were built on speculative hiddens and must be corrected here. At k = 1 the loop's only input is the verified carry, so slot t needs no correction — column 0 is dead weight and step ③ could run at T=1.

Why slot t+1 needs a second draft invocation
By the slot rule, slot t+1 is by definition built from ht+1 — and ht+1 is a verify output. At step ① it did not exist, and neither did the token at t+2. There is no way to synthesize a KV entry other than running the layer, so it costs a second pass.

Checkpoint restoration

Four mechanisms, one per store

1 · DeltaNet S and conv — explicit select _commit_deltanet :4488

A linear recurrence folds each token irreversibly into the state. You cannot truncate it like a KV cache, and inverting the exp(cumulative log-decay) gate is numerically unsafe on this checkpoint. So: run forward only, checkpoint per position, select.

out.append(torch.where(sel_s, S_stack[:, 1], S_stack[:, 0]).to(dtype))   # S₂ : S₁
out.append(torch.where(sel_c, conv_cand[:, 1], conv_cand[:, 0]).to(dtype))
  • In-graph torch.where — never the eager offset-strided [:, idx] view, which XLA lowers wrong.
  • Selected states ride back into the live buffers through the aliased state region: Qwen36FusedSpecModelInstance inserts ns committed states at [base, base+ns) and shifts the rolling hidden to base+ns. :4675
  • The carry is rounded to buffer dtype (bf16) between steps :675 so verify matches sequential TKG decode bit-for-bit; the step math still runs in fp32.

2 · GQA KV — overwrite, no rollback

Verify writes both positions in place. On reject, position t+2 holds an entry for a token that was never emitted — but next round's position_ids rewind to t+2 and overwrite it before anything reads it. Nothing to undo.

3 · MTP KV — replay, then overwrite

The head writes 2 slots per round (t and t+1), but only index + 1 of them survive. Unrolled at t = 10, carry (x₁₁, h₁₀) — x̂ = draft, x = verified:

round A   ① slot 10 ← (h₁₀, x₁₁)              drafts x̂₁₂
          ② verify [x₁₁, x̂₁₂]  →  h₁₁, h₁₂ ·  x₁₂ = argmax(h₁₁) ·  x₁₃ = argmax(h₁₂)
          ③ slot 10 ← (h₁₀, x₁₁)    redo
            slot 11 ← (h₁₁, x̂₁₂)    new
✓ accept · index = 1 · advance 2
Emit x₁₂, x₁₃. Carry (x₁₃, h₁₂) → t' = 12.
Round B ① writes slot 12 and attends over slot 11, which holds (h₁₁, x̂₁₂) — and x̂₁₂ = x₁₂, so it is exactly right.
Slots 10, 11 permanent. 2 slots · 2 tokens
✗ reject · index = 0 · advance 1
Emit x₁₂ only. Carry (x₁₂, h₁₁) → t' = 11.
Round B ① writes slot 11, clobbering (h₁₁, x̂₁₂) with (h₁₁, x₁₂) before any read.
Slot 10 permanent. 1 slot · 1 token
Invariant
Committed MTP slots per round = tokens emitted per round. The speculative extra write is always reclaimed, because a reject rewinds t to exactly the slot it wrote — the same self-cleaning property as the GQA KV. No truncation anywhere.

4 · Rolling hidden — gather :4604

gather(hidden, index) picks ht+1 on reject or ht+2 on accept — the hidden at the last accepted position, which seeds next round's draft. Consumed by the parent forward's set_state.

Why nothing branches
The graph is static-shape and AOT-compiled — there is no if accepted. Every path is computed for both outcomes and then selected: two DeltaNet candidates, two hiddens, an unconditional replay. The only dynamic value is index, and it is used exclusively as a where/gather operand. Steps ③ and ④ are therefore order-independent — the replay runs first purely because it doesn't depend on the accept.

Graph output

Return layout :4612

[candidate_input_ids, target_tokens] + draft_kv + target_kv + committed + [hidden]
  • committed is flat [rec₀, conv₀, rec₁, conv₁, …] in _deltanet_state_params order — aliased, not returned to host.
  • hidden (last) feeds the rolling buffer.
  • Emitted tokens = index + 1, and are bit-identical to plain greedy decoding. Speculation changes throughput only.
